# MVP product spec

## 1. Cél
Az MVP célja egy működő, zárt bétás Android-alkalmazás létrehozása, amelyben a felhasználók admin által létrehozott retorikai szituációkra rövid reakciókat küldenek be, mások reakcióit elolvashatják, és egyszerű like-alapú visszajelzést adhatnak.

Az MVP nem teljes közösségi ökoszisztéma. Az MVP egy magmechanika-validáció.

## 2. Maghipotézis
Ha a felhasználók egy világos, retorikai megoldást igénylő szituációra reakciót írhatnak, majd más reakciókat elolvashatnak és like-olhatnak, akkor ebből elég erős alapélmény keletkezhet ahhoz, hogy legyen továbbfejleszthető termék.

## 3. Célközönség az MVP-ben
- szöveg- és kommunikációérzékeny korai tesztelők
- olyan felhasználók, akiket érdekel a retorikai helyzetmegoldás
- zárt béta környezetben kipróbálók, nem tömegpiaci indulás

## 4. Product identity
A termék identitása az MVP-ben:
- intelligens
- letisztult
- enyhén kompetitív
- szövegközpontú
- kulturált

Nem cél:
- mémes közösségi tér
- kommentes káosz
- propaganda-játék érzet
- általános fórum

## 5. Fő MVP funkciók
- regisztráció és belépés
- alap profil
- szituációlista
- szituáció részletes oldal
- reakció beküldése
- reakciók olvasása
- like / unlike értékelés
- admin szituációlétrehozás
- minimum moderációs eszközök

## 6. Ami nincs az MVP-ben
- klubok / csapatok
- challenge-ek
- szezonok
- badge-ek, rewardok
- kommentrendszer
- felhasználói szituációbeküldés
- többdimenziós pontozás
- reputációs súlyozás
- vak párbaj
- publikus nyitott indulás
- fizetős csomagok

## 7. Fő user flow-k
### 7.1. Új user
1. letölti az appot
2. regisztrál
3. megad egy display nevet
4. megérkezik a szituációlistára
5. megnyit egy szituációt
6. elolvassa a briefet
7. reakciót küld be
8. elolvassa mások reakcióit
9. like-ol, ha akar

### 7.2. Visszatérő user
1. belép
2. megnézi az aktív szituációkat
3. új reakciókat olvas
4. like-ol
5. új szituációra reagál

### 7.3. Admin
1. belép adminként
2. admin felületre lép
3. új szituációt hoz létre
4. kezeli a minimális moderációs feladatokat

## 8. MVP sikerfeltételek
Az MVP akkor tekinthető működőnek, ha:
- a teljes alap user flow végigfut
- admin tud szituációt létrehozni
- user tud reagálni
- user tud like-olni és unlike-olni
- a reakciók listája stabilan olvasható
- a minimum moderáció működik
- a zárt béta környezetben használható az app

## 9. Design elv
A felület fókusza:
- a szituáció brief
- a reakcióírás
- a reakciólista

A vizuális dizájn ne nyomja el a tartalmat.

## 10. MVP kockázatkezelés
Az MVP-szinten minimalizálandó kockázatok:
- túl sok funkció
- túl korai közösségi komplexitás
- túl bonyolult pontozás
- kommentes toxikusság
- gyenge moderáció
